# 杏林汇 · 世界顶尖级中医诊疗系统建设方案

> 版本 v1 · 2026-08-28
> 目标:把杏林汇从"四科合一的辅助诊疗平台"进化为世界顶尖级中医诊疗系统。
> 三个视角:中医需求(专业深度)、病患(体验与信任)、高级软件工程(架构与技术卓越)。

---

## 〇、现状基线(方案起点)

已具备:知识总库 3,540 条(方剂 670/中药 1960/病种 115/证型 59/医案 133/要诀 310/术语 48/引药 245)、四科原版辨证引擎(儿科程氏八症/疮疡消托补三期/痔漏结构化置信度/丹药红旗问诊)、统一辨证中心(规则+DeepSeek+Qwen-VL)、AI 原文溯源、门诊工作流(四诊→辨证→处方→PDF→随访→导出)、学苑(学习路径/自测/AI 助教)、设备级免登录隐私、移动端适配、四原版系统并存、GitHub 备份、双轮审计(功能/安全)通过。

差距:辨证体系单一(缺八纲/六经/卫气营血/三焦)、知识限于四专科、检索是 ILIKE 非语义、AI 无评测体系、无可观测性、无 CI/CD、病患侧缺全病程与可视化、无国际化。

---

## 一、中医需求角度(专业性 = 世界级的根基)

### 1.1 辨证论治体系补全(核心命题)
- **多辨证体系并行**:在现有四科特色辨证之上,建立标准化的**八纲→脏腑→六经→卫气营血→三焦**辨证链;一次四诊输入,输出多体系对照结论,注明各体系适用场景(如外感用六经/卫气营血,内伤用脏腑)。
- **证候相兼与传变**:证型之间建立"相兼/转化/传变"关系(如卫→气→营→血、太阳→阳明),辨证结果附带**传变预警与截断建议**(治未病)。
- **四诊结构化深化**:脉诊 28 脉象逐项采集与机理解释、舌诊分区(舌尖/中/根/边)建模、闻诊与按诊标准化条目。
- **治则治法库**:治则(正治/反治/标本缓急/同病异治)与治法(汗吐下和温清消补)结构化,与方剂自动挂接。

### 1.2 经典知识全集化
- **典籍原文库**:《黄帝内经》《伤寒论》《金匮要略》《温病条辨》《神农本草经》等核心典籍全文检索(现有丹药/儿科原书数字化的模式推广),每条知识标注**出处+原文+白话**。
- **药物数据库升级**:每味药补全性味/归经/毒性/炮制/剂量上限/十八反十九畏/妊娠禁忌(部分已有);**君臣佐使**方剂结构建模。
- **经方体系**:经方(伤寒金匮方)+时方+专科验方分层,标注加减法来源原文。
- **循证分级**:每条结论标注证据等级(经典原文/名家经验/现代临床研究),AI 输出必须附等级与出处。

### 1.3 专科模块化扩展
- 现有四科(疮疡/肛肠/儿科/丹药)作为样板,**模块化接入内科/妇科/皮肤/骨伤/耳鼻喉/针灸推拿**等专科(数据结构已支持 module 标签)。
- 每专科 = 病证方药数据 + 专科辨证规则引擎 + 特色问诊(如儿科四步采集模式)。

### 1.4 AI 中医深度
- **领域 RAG**:知识库向量化(pgvector),AI 辨证与答疑严格基于原文检索(已具雏形,升级为语义检索+重排)。
- **辨证 AI 协商式交互**:AI 不是一次出结果,而是"AI 初诊 → 医生逐项确认/修改 → AI 复诊"的对话式辨证(像名医会诊)。
- **中医评测集**:建立"症状→证型→方剂"标准评测集(由医师标注),每次模型/提示词变更自动回归,公开辨证准确率。

### 1.5 传承与安全
- 丹药/毒性药物**红旗体系**扩展到全库(马钱子/汞剂/细辛剂量等),剂量超限自动拦截;
- 危急重症识别(现有儿科危候模式推广)与转诊提示。

## 二、病患角度(体验与信任 = 世界级的感知)

### 2.1 可信与安全
- 全程"**辅助参考,非处方**"声明与 AI 内容标注(已有基础,强化);
- **危急拦截**:输入症状时实时识别危重信号,红色提示立即就医;
- **隐私**:设备级匿名已是基础;升级为**数据本地优先/可删除权**(一键清除本设备全部记录),未来涉真实患者数据时合规(等保/告知同意)。

### 2.2 易懂与可视化
- 术语白话解释全覆盖(点术语即出白话+出处);
- **辨证可视化**:体质雷达图、症状-证型关联图、处方君臣佐使关系图、疗效趋势图;
- 图解/视频:舌象图谱、脉象示意、儿科指纹十八图式(已有图谱基础)。

### 2.3 全病程陪伴
- **诊前**:症状自查(红旗分层)、体质辨识(九种体质问卷);
- **诊中**:四诊引导、AI 协商辨证、处方与煎服指南;
- **诊后**:服药提醒、复诊提醒(已有)、**疗效自评**、调方建议、健康档案时间线;
- **节气养生**:五运六气/节气养生内容(本地已有素材)接入病患首页。

### 2.4 个性化与多端
- 按体质/病种生成个性化调护方案(食疗/起居/导引);
- 移动端(已有基础)→ PWA/小程序;**语音输入四诊**(老年友好);
- 无障碍:大字模式、高对比度、屏幕阅读器支持(WCAG AA)。

### 2.5 信任建设
- 医师/专家资质展示、经典出处可查、AI 决策可解释(证据链);
- 数据导出权(已有就诊导出)+ 删除权;
- 公开的辨证准确率报告与安全说明。

## 三、高级软件工程师角度(架构与技术卓越)

### 3.1 架构演进
- **模块化单体 → 边界清晰的服务化**:按领域拆分模块(知识库/辨证引擎/AI 网关/门诊/用户/统计),DDD 聚合根(患者/证型/方剂);先模块化单体(短中期),远期按负载拆分微服务。
- **事件驱动**:随访提醒、AI 任务、通知走 Redis 队列(Celery 或 arq);AI 长任务异步化+流式输出。
- **数据层**:知识库升级为 **PG + pgvector**(语义检索替代 ILIKE)+ 关系化知识图谱(证-方-药-症-病 实体关系);知识版本化(经典条目不可变,修订留痕)。

### 3.2 AI 工程化(平台的核心竞争力)
- **模型网关**:DeepSeek/Qwen 等多模型路由、统一限流/熔断/重试/缓存、**成本计量**(每次辨证成本可见);
- **RAG 管道**:切片/向量化/混合检索(BM25+向量)/重排,提示词版本化;
- **输出结构化**:AI 输出 JSON Schema 校验+自动修复,杜绝格式漂移;
- **评测体系**:辨证评测集 + 双盲评估 + CI 中自动回归;AI 质量看板。

### 3.3 可靠性与可观测性
- 结构化日志+指标(Prometheus)+链路追踪;Sentry 错误追踪(接入,当前 DSN 为空);
- **CI/CD**:GitHub Actions(测试→构建→灰度发布→自动回滚);SLO 99.9%;
- 备份/灾备自动化(现有基础,补异地备份);灰度发布(新辨证规则先 5% 流量)。

### 3.4 性能
- 语义检索(向量)替代全表 ILIKE(当前 3.5k 数据可接受,但为世界级需上向量);
- 缓存分层(Redis 已有):知识条目/AI 结果缓存;分页/索引优化;前端按路由懒加载+chunk 优化(已做)。

### 3.5 安全与合规
- 密钥集中管理(环境变量已做,升级 secret 管理)、全站 HTTPS(已做)、WAF、审计日志;
- 上传安全(已做 magic 校验,补完整解码重编码)、限流(已做,升级 Redis 分布式限流);
- 合规:面向世界市场需按地区合规(中国等保、欧盟 GDPR);建立隐私政策与数据删除机制。

### 3.6 开放平台与国际化
- **开放 API**:辨证/知识库 API 供第三方与科研(带 API Key 与计量);
- **插件化专科**:专科模块以插件形式接入(数据+引擎+问诊模板);
- **国际化**:多语言(i18n,先中/英)、中医术语双语对照、面向海外中医教育与诊所;
- 实时能力:WebSocket(辨证流式输出、随访提醒推送)。

### 3.7 质量与测试
- 单元/集成/E2E/契约测试;辨证规则**回归测试集**(规则变更自动验证);
- 可访问性测试、性能基准、混沌演练(限流/故障注入)。

## 五、成功指标(KPI 草案)
- **专业性**:辨证评测集准确率 ≥85%、结论可溯源率 100%、危急拦截漏报 0;
- **病患**:NPS ≥50、复诊率提升、页面 P95 <2s、可访问性 AA;
- **工程**:测试覆盖率 ≥80%、SLO 99.9%、Critical 漏洞 0、部署频率 ≥1/周、AI 成本/次可控且可观测。
